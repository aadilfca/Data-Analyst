Also hosts Rate derivation at import time: `get_rate_precision()` (reads the `rate_precision` app_settings key), `find_named_column()` (case-insensitive/trimmed column_name lookup), `resolve_upload_rate_source(template_cols, col_mapping)` (Phase B of the Rate Source 'auto' requirement — resolves a template's `'auto'` into a concrete `'imported'`/`'derived'` once per upload, based on whether *this upload's own* column mapping actually maps a Rate column, not the template's static definition; called once in `validate_and_import()` right after `rate_source`/`col_mapping` are read, before that resolved value fans out to `compare_transactions()` and every storage write), and `apply_rate_derivation(row_data, template_cols, rate_source, rate_precision)` — for Purchase Order/Store Receiving/Vendor Bill templates only, computes `row_data['Rate']` as Amount ÷ Quantity when `rate_source='derived'` (Quantity missing/blank/0 leaves Rate as `None`, never an error) or rounds an already-imported Rate column when `rate_source='imported'`, both rounded to `rate_precision` — this function always receives an already-resolved `'imported'`/`'derived'` value, never the literal `'auto'`. Called in `compare_transactions()`'s incoming-row loop and `validate_and_import()`'s first-time-upload branch — **must stay before change-detection's diff runs**, or every re-upload of an already-imported row looks artificially "changed" (a stored row already carries a Rate value; a freshly-rebuilt comparison row without one injected first would never match). `validate_only()` is deliberately untouched. `reorder_row_data_by_template()` runs right after both call sites to keep `row_data`'s stored key order matching the template's `sort_order`. `client_data.rate_source TEXT` (nullable) is the per-row audit trail of how that row's Rate was actually obtained, set at all 3 write points from the already-resolved `rate_source` variable, recorded even when Rate itself is null. `extract_columns_from_row()`'s amount/date extraction uses independent found-flags (not a shared `break`) and prefers a column literally named "Amount" over "first Numeric column" — see "Rate-Derivation Requirement" in CHANGELOG_ARCHIVE.md for the full design, the historical `extract_amount`-was-always-NULL bug, and both one-time backfill scripts (`backfill_rate.py`, `backfill_extract_amount.py`).

**Purpose:** Rotating quality check across the app — no full-code reads, fixed budget, findings-only (no code changes during review).

- Max 5–8 files per session.

**Rotation:**
1. **Module correctness pass** — one module's core logic files.
2. **Cross-cutting pattern pass** — search whole codebase for one known risk pattern.
