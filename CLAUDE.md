## Conventions
- No inline event handlers (onclick, onload) in HTML
- No <script> inside HTML containers
- Meaningful comments on new/changed code
- In static/style.css, `.modal-content` and `.modal-header` are NOT shared base classes — each existing modal (#supportingModal, #procedureModal) defines its own `#<modalId> .modal-content` / `#<modalId> .modal-header` rules. When adding a new modal, add its own id-scoped rules rather than relying on `.modal-content`/`.modal-header` alone to style it.
- Keep changes scoped — don't touch unrelated code
- Document grouping (get_document_group_id in routers/import_export.py) assumes the first template column (lowest sort_order) is a unique document key. Do not reorder template columns without checking this assumption holds.
- static/verification.js: several class names are targeted by *unscoped* `document.querySelectorAll('.classname')` inside `renderTransaction()` (currently `.segment2-tab-btn`, `.segment2-tab-panel`, `.clickable-proc`) rather than being scoped to a container. When adding new elements elsewhere on the page that need their own independent click/tab behavior, do not reuse these exact class names for the JS hook — `renderTransaction()`'s listeners will also bind to them and corrupt cross-element state (e.g. resetting a target variable, or toggling `.active` on every matching element in the document). Give new elements a distinct class name for the JS hook and, if the same visual styling is wanted, extend the existing CSS rule's selector list (e.g. `.segment2-tab-btn, .voucher-line-tab-btn { ... }`) rather than reusing the class outright.
- static/verification.js: `#transactionCard`'s own Segment 2/3 (inside `renderTransaction()` — type dropdown, AUDIT panel, procedure cards) is a leftover duplicate of the active voucher line's Segment 2/3 in `#voucherLinesContainer`, kept by deliberate Phase 3/4 decision rather than reconciled. As of Phase 4, edits made through `#transactionCard`'s copy are **not saved** — `saveLineItems()`/`saveAllVoucherLines()` read exclusively from `voucherLineState` (the per-line rows), never the bare `procedureData`/`currentTransactionType` globals that `#transactionCard`'s own listeners still write to. If a future session needs `#transactionCard`'s duplicate to actually work (or decides to remove it), start by reading the Phase 3/4 entries above.
